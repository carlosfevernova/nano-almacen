## Why this exists

**The Mexican corner-store market:** 5.9M "tienditas" and "abarrotes" that:
- Take 64% of their orders via WhatsApp (highest LatAm penetration)
- Pay a bookkeeper 500-1,500 MXN/month just to issue SAT-compliant CFDI 4.0 invoices
- Track credit ("fiado") in physical notebooks that get lost
- Are ignored by Enterprise ERPs (Bind, Contpaqi) and generic global POS (Loyverse, Toast)

**Meta Business AI launched Mexico-first (Nov 2025)** — huge unlock, but Meta only covers chat. Doesn't touch inventory, CFDI, credit ledger, or proactive outreach. That gap is where Nano-Almacén lives.

## What's built (production-ready)

- **Public landing** (ES-MX) with waitlist → Supabase persist
- **WhatsApp order parser** via Gemini 3.5 Flash Lite with Zod-validated output. Spanish-MX context: parses "5 chelas y 2 sabritas" → structured JSON. Free tier: ~1,500 req/day.
- **Catalog upload** (Excel via exceljs + photo via Gemini Vision). Fuzzy header matching for MX Spanish column names. Auto-upsert with idempotent conflict resolution.
- **Dashboard tendero** server-rendered with 4 KPI cards + recent orders/messages/catalog tables.
- **Fiado (credit ledger)** — the killer cultural feature every Mexican shop needs. Alegra/Bind ignore it, Treinta does it basically. Full ledger + trigger-driven balance updates + one-click WhatsApp reminder generator with contextual message.
- **Multi-tenant DB** — 10 tables, Row-Level Security, atomic RPCs, triggers. Migrations idempotent.

## Design decisions

**Why Gemini** — most generous free tier (1,500 req/day) for parse + Vision. Zero-cost inference is a huge unlock for $19-49 MXN/mo pricing. Structured output + Zod = Claude-tier reliability at $0.

**Why Supabase** — RLS-first model + `auth.users` integration made multi-tenant scaffolding a 1-day effort vs 5-day equivalent. Migration to dedicated instance is trivial.

**Why Next.js 16** — App Router + Server Components + Turbopack production support = simplest full-stack setup. Trade-off: `middleware.ts` renamed to `proxy.ts` in Next 16 (small friction, big upside).

**Why exceljs (not xlsx)** — `xlsx` had 8+ CVEs unpatched. `exceljs` is actively maintained and CVE-free.
